업무용 프로그램 개발 표준 세부 기획서 Form
==================================
# 업무용 프로그램 개발 표준 세부 기획서 Form

**버전:** 1.4
**기준 제품:** aiAssistant / 통합 AI 업무 어시스턴트
**작성 기준일:** 2026-10-19
**쓰는 범위:** Flutter 웹 PWA, Node.js, Firebase 또는 Supabase, GitHub, Vercel 또는 Netlify로 만드는 프로그램. 업무 프로그램과 개인 도구에 같은 칸을 쓴다. 생성형 AI를 붙이는 프로그램도 같은 칸을 쓴다.
**기준:** 1.3의 고정 규칙, 계정, 자산 생성, 점검 절차. 1.3은 TempBox로 칸을 채웠다. 1.4는 같은 서식을 aiAssistant 완성본으로 채우고, aiAssistant가 확정한 값으로 기본값을 고친 문서다. AI 판단, 주 DB와 보조 DB, 읽기 설정, 행 펼치기를 기본값에 더했다.
**폴더:** `lib/app`(또는 `lib/main.dart`), `lib/pages`, `lib/features`, `lib/shared`, `functions/`, `web/brand/`, `app_icons/`, `tool/`
**용어:** 로그인하지 않은 사용자는 **비회원 사용자**다. 화면 문구는 `게스트`이고 구현은 익명 인증이다. 데이터가 없는 화면은 **데이터 없음 상태**다. 사용자의 말을 AI가 해석한 결과는 **의도(intent)** 다.
**코드 기본 언어:** 필드, 함수, 저장 경로, 오류 코드, 이벤트 코드는 영어다. 화면에 보이는 문장만 한국어, English, 日本語로 바뀐다.
**비밀:** API 키, AI 키, 서비스 계정, OAuth 비밀, 관리용 ID는 이 문서와 화면과 클라이언트에 적지 않는다. 키는 이름만 적는다.

## 1.3에서 1.4로 확정한 기본값

1. 화면 언어는 한국어, English, 日本語 순서다. 헤더의 언어 버튼은 누를 때마다 다음 언어로 바뀐다. 마이페이지와 로그인 화면에는 세 버튼이 함께 있다.
2. 화면은 세 프레임이고 비율로 나눈다. 너비가 높이 이하면 스마트폰 세로, 가로이면서 높이 600 미만 또는 너비 820 미만이면 스마트폰 가로, 그 외는 데스크톱이다. 프레임마다 레이아웃 파일이 따로 있고, 실행 중 바로 바뀐다.
3. 마이페이지는 모든 프레임에서 헤더의 아바타 버튼이다. 로그아웃도 모든 프레임의 헤더에 보인다.
4. 생성형 AI는 서버가 부르고, 정해진 JSON 스키마로만 답을 받는다. 메뉴와 저장 방식은 정해진 값(enum) 중에서만 고르게 한다. 저장할 때 꼭 있어야 하는 칸(일정 시각, 장부 목록)은 필수 칸으로 둔다. 키워드 포함 여부로 메뉴를 고르지 않는다.
5. AI가 저장을 말했는데 서버가 저장하지 못하면 성공 문장을 쓰지 않는다. 아무것도 저장되지 않았으면 한 번만 다시 묻고, 그래도 실패하면 사실대로 알린다.
6. 주 저장소는 Firestore의 이름 있는 DB 하나다. 같은 프로젝트에 보조 DB를 두고, 서버 트리거로 모든 사용자 문서를 복제한다. 주 DB를 읽을 수 없을 때만 보조 DB에서 읽는다. 두 DB 모두 삭제 보호를 켠다.
7. Cloud Functions 런타임은 Node.js 22다.
8. 서비스 워커를 쓰지 않는다. `index.html`은 예전 빌드가 남긴 서비스 워커와 캐시를 지우고 한 번 새로고침한다.
9. 마이페이지에 글자크기 5단계(기본 3단계, 단계마다 ±10%)와 줄간 거리 5단계(기본 4단계, 단계마다 ±10%)를 둔다. 모든 화면에 적용되고 기기에 저장된다.
10. 목록 행은 접힌 상태가 기본이다. 스마트폰은 한 번 탭, 데스크톱은 더블클릭으로 그 행만 펼치고 접는다. 체크는 체크박스를 눌렀을 때만 된다.
11. 설치 아이콘은 원본 한 장(`app_icons/app_icon_master.png`)에서 스크립트(`tool/make_icons.py`)로 만든다. any 6종, maskable 2종, apple-touch 180, favicon 16·32·ico를 만든다. `manifest.json`에는 `id`와 `scope`를 `/`로 둔다.
12. 로그인 수단은 이메일+비밀번호, 휴대폰+비밀번호, Google, 게스트다. `로그인 상태 유지`를 끄면 그 탭에서만 로그인이 유지된다.
13. 가짜 시세, 가짜 날씨, 시드 데이터를 넣지 않는다. 데이터 없음 상태와 실제 서버 호출만으로 핵심 시나리오가 끝나야 한다.

## 쓰는 절차

1. 섹션 1의 아이디어 칸을 시나리오와 스토리로 채운다. 1.4의 섹션 1은 aiAssistant로 채워져 있다.
2. 공통 고정 정책과 칸에 적힌 1.4 기본값은 그대로 둔다. 시나리오가 기본과 다를 때만 그 칸을 고치고, B-00-12에 이유를 적는다.
3. 시나리오에 없는 기능은 `해당 없음`과 이유를 적는다. 빈칸은 미정이므로 코딩으로 넘기지 않는다.
4. AI를 쓰면 B-06-09부터 B-06-16까지 채운다. 쓰지 않으면 `해당 없음`이다.
5. 섹션 8 절차로 프롬프트 7종을 만들어 `web/brand/prompts.md`에 둔다.
6. 섹션 20이 모두 `예`이면, 섹션 21 골격으로 개발 Agent 프롬프트를 쓴다.

## 시나리오에서 칸으로 옮기는 규칙

- 사용자가 하는 동사는 섹션 1의 핵심 동작이 되고, 통계를 쓰면 섹션 10의 사건이 된다.
- 사람 관계가 "혼자" 또는 "나의 다른 기기"이면 조직 권한은 `해당 없음`이다.
- 사용자가 말로 시키는 일은 B-06-10의 AI 의도 목록이 된다. 의도 하나마다 서버 함수 하나와 실패 문장 하나가 있어야 한다.
- 외부 API로 조회한 결과는 보존 시간이 있는 기록이다. 섹션 7에 시간을 숫자로 적는다. 사용자가 만든 기록은 기본값 `유지`(사용자가 지울 때까지)다.
- 메뉴가 여러 개면 메뉴마다 B-04 행과 B-07 필드를 적는다.
- 파일이 없으면 용량과 형식은 `해당 없음`이다. 파일이 있으면 섹션 6의 기본 용량을 쓰고, 다른 크기는 그 칸을 고친다.
- 화면 문장은 섹션 1의 성공, 실패, 데이터 없음 문장을 그대로 쓴다.
- 아이콘과 상태 그림의 장면은 한 줄 약속과 스타일 문장으로 섹션 8 틀에서 만든다.

## 공통 고정 정책

1. 생성 확정, 수정 확정, 삭제, 만료, 용량, 권한, 집계, 외부 조회 결과 저장은 Node.js 서버가 확정한다. 클라이언트는 입력과 화면을 담당한다.
2. 서버가 성공하기 전에는 화면에 반영 완료를 보이지 않는다. 실패하면 이전 상태와 이유를 보여 준다.
3. 주 저장소는 Firebase 또는 Supabase 중 하나다. 키는 그 프로그램에서 새로 발급한다.
4. 관리용 ID를 쓰면 영문 대문자로 시작하는 영문 대문자와 숫자 16자다. 서버가 만든다. 화면, 목록, 통계, 클라이언트가 읽는 문서에 넣지 않는다.
5. 시스템 관리자 권한은 서버 클레임만 사용한다. Firebase는 `admin=true`, Supabase는 `app_metadata.role=admin`이다. 비밀번호와 관리자 계정을 소스, 시드, 환경 예시, 코딩 프롬프트에 넣지 않는다.
6. 비밀번호는 인증 제공자만 저장한다. 데이터베이스에 비밀번호나 해시를 쓰지 않는다.
7. 로그인 실패 문장은 계정 없음과 비밀번호 틀림을 구분하지 않는다.
8. 탈퇴 문안과 실제로 지우는 데이터, 남는 데이터가 같다.
9. 데이터 없음 상태와 실제 서버 호출만으로 핵심 시나리오가 시작부터 끝까지 가능해야 한다. 가짜 데이터와 시드 데이터는 넣지 않는다.
10. 개발용 진단은 개발 빌드에만 있고 프로덕션 빌드에는 없다.
11. 문안은 i18n으로 분리한다. 기준 문안은 한국어다. 화면 언어는 한국어, English, 日本語다. 코드와 데이터베이스 항목은 영어다.
12. 로그아웃과 마이페이지는 모든 프레임의 헤더에서 한 번에 닿는다. 기본 배치는 오른쪽 위 `[로그아웃] [마이페이지]`다. 다르면 B-09-04와 B-00-12에 적는다.
13. 참고 제품의 정보 구조는 써도 된다. 로고, 이름, 아이콘 파일은 이 프로그램의 것으로 만든다.
14. 관리자 화면과 통계 화면은 본문, 파일 바이트, 비밀번호, 관리용 ID를 그리지 않는다.
15. 섹션 8의 프롬프트와 폴더를 만든 뒤 아이콘, 썸네일, 상태 그림을 넣는다.
16. GitHub `main`에 푸시하면 Vercel 또는 Netlify에 배포하고, 새로고침에 대비해 모든 경로를 `index.html`로 보낸다.
17. 서비스 워커는 기본으로 쓰지 않는다. 쓰는 경우에도 개인 파일 바이트와 서명 주소는 캐시하지 않고, 배포마다 갱신된다는 것을 확인한다.
18. 비회원과 로그인 사용자는 서버의 인증 정보로 구분한다. 클라이언트 플래그로 자격을 바꾸지 않는다.
19. 감사 로그에는 행위, 행위자, 대상 ID, 시각, 바뀐 필드 이름만 남긴다. 본문과 이전 값은 남기지 않는다.
20. `해당 없음`과 MVP 이후로 적은 기능은 구현하지 않는다.
21. AI 판단은 서버가 스키마 JSON으로 받고, 저장은 서버 코드가 값을 검증한 뒤 실행한다. 키워드 분기로 메뉴를 고르지 않는다. 저장하지 못했으면 성공 문장과 저장 표시를 쓰지 않는다.
22. 외부 API 키와 AI 키는 서버 비밀(Secret Manager)에만 둔다. 웹 번들, `.env`, 문서에 넣지 않는다. 로컬 실행용 비밀 파일은 배포와 git에서 제외한다.
23. 주 DB는 삭제 보호를 켠다. 보조 DB가 있으면 서버 트리거로만 복제한다. 클라이언트는 보조 DB에 쓰지도 직접 읽지도 않는다.
24. 클라이언트는 Firestore를 자기 uid 아래만 읽는다. 쓰기는 모두 Admin SDK가 한다.

예외는 B-00-12에만 적는다. 없으면 `없음`이다.

**프레임**

- 판정: 너비가 높이 이하면 스마트폰 세로. 가로이면서 높이 600 미만 또는 너비 820 미만이면 스마트폰 가로. 그 외는 데스크톱.
- 데스크톱: 왼쪽 위에 로고, 그 아래 큰 보드. 보드 위쪽은 노란 상단 바(너비 1180 이상이면 높이 128, 아니면 118)다. 상단 바 왼쪽은 로봇(누르면 대화 홈)과 그 아래 로그아웃이고, 가운데는 메뉴 타일 6개, 오른쪽은 언어 버튼과 아바타(마이페이지)다. 홈은 대화만 보이고(최대 너비 980), 메뉴를 열면 대화 46 : 메뉴 54로 나뉘며 사이에 점선이 있다.
- 스마트폰 가로: 왼쪽에 너비 58의 노란 레일(로고는 홈, 아이콘 타일 6개). 위쪽 띠에 로고, 언어, 아바타, 로그아웃. 대화 47 : 메뉴 53.
- 스마트폰 세로: 헤더에 로고(홈), 언어, 아바타, 로그아웃(너비 370 미만이면 아이콘만). 대화 42 / 메뉴 58. 맨 아래 노란 탭 바에 아이콘 6개. 키보드가 올라오면 메뉴 패널과 탭 바를 숨긴다.
- 메뉴 패널 위에는 메뉴 색 띠와 이름, 닫기 버튼이 있다. 마이페이지도 같은 패널에 열린다.
- 회전하거나 크기가 바뀌어도 선택한 메뉴, 입력 중인 문장, 계산 상태, 팝업 위치를 버리지 않는다.

## 7. 데이터 수명과 이력

```text
입력(텍스트·음성·파일) → 서버가 AI 의도를 받음 → 서버가 검증하고 저장 또는 조회
→ 실시간 스트림으로 화면에 보임 → 트리거가 보조 DB에 복제
→ 사용자 삭제 또는 120시간 만료(날씨·환율) → 주 DB에서 삭제 → 트리거가 보조 DB에서도 삭제
```

|---|---|---|---|

## 10. 통계

aiAssistant는 `해당 없음`이다. 혼자 쓰는 도구이고 관리자 화면이 MVP 밖이다. 다음 제품이 통계를 쓰면 아래 기본값을 그대로 쓴다.

| ID | 구분 | 항목 | 기입 |
|---|---|---|---|
| B-10-01 | 필수 | 사건 | 해당 없음. 기본값은 핵심 동작의 동사(created, updated, deleted, expired, rejected)이고, 화면 표시 이름만 선택 언어로 바뀐다 |
| B-10-02 | 기본 | 칸 | 기본값: 사건마다 비회원과 로그인 사용자를 나눈다 |
| B-10-03 | 기본 | 화면 | 기본값: 막대 1개와 표 1개. 열은 날짜, 사건, 비회원 수, 로그인 수, 합계 |
| B-10-04 | 기본 | 기간 | 기본값: 7일. 7, 30, 90일 중에서 고른다 |
| B-10-05 | 기본 | 없음 / 내보내기 | 기본값: `이 기간의 기록이 없습니다.` 화면에 보이는 표만 CSV로 내보낸다 |
| B-10-06 | 기본 | 중복 방지 | 기본값: 실패한 요청은 세지 않는다. 같은 대상의 같은 사건은 한 번만 센다 |
| B-10-07 | 기본 | 일반 사용자에게 보여줄 숫자 | aiAssistant: 마이페이지의 자기 대화 기록 건수, 주 DB와 보조 DB의 자기 문서 건수 |

통계 문서는 `stats/{yyyyMMdd}`이고, 서버가 성공한 뒤에만 갱신한다. uid, 이메일, 전화, 본문, 파일명은 넣지 않는다.

**탈퇴.** `탈퇴`를 누르면 확인 대화상자에 `계정과 일정, 장부, 뉴스, 날씨, 환율, 대화, 업로드 파일을 삭제합니다.`가 뜨고, 붉은 `탈퇴` 버튼으로 확정한다. 서버는 6개 컬렉션, 그 사용자의 감사 로그, `uploads/{uid}/` 파일, `users/{uid}` 문서, 보조 DB의 `users/{uid}` 전체, Auth 사용자를 지운다. 그 뒤 로그아웃하고 로그인 화면으로 간다. 기기의 계산 기록과 화면 설정은 그 브라우저에 남는다(남은 일: 문안에 적거나 함께 지운다).

**유휴.** 없음. `로그인 상태 유지`(기본 켜짐)로 LOCAL 또는 SESSION 유지 방식을 고른다.

## 19. 개발 프롬프트 앞에 붙이는 문장

1. 생성, 수정, 삭제, 만료, 용량, 권한, 외부 조회 저장, 잔액 계산은 Node.js 서버가 확정한다.
2. 서버가 성공하기 전에는 화면에 반영 완료를 보이지 않는다.
3. 관리용 ID를 쓰면 화면, 통계, 클라이언트가 읽는 문서에 넣지 않는다.
4. 데이터 없음 상태와 실제 서버 호출만으로 핵심 시나리오가 끝나야 한다. 가짜 데이터와 시드 데이터를 넣지 않는다.
5. 개발용 진단은 프로덕션 빌드에 없다.
6. 주 저장소는 이 프로그램의 Firebase 또는 Supabase 하나다. 다른 프로그램의 키를 넣지 않는다.
7. 소스, 시드, 환경 예시에 관리자 비밀번호와 API 키를 넣지 않는다. 키는 서버 비밀로만 둔다.
8. 참고 제품의 로고와 아이콘 파일을 넣지 않는다.
9. 서비스 워커를 쓰지 않는다. 예전 서비스 워커는 index.html에서 지운다.
10. 통계와 관리 화면에 본문과 파일 바이트를 그리지 않는다.
11. 섹션 8의 프롬프트 7종을 `web/brand/prompts.md`에 쓰고, 아이콘은 원본 한 장에서 스크립트로 만든다.
12. 통계를 쓰면 비회원과 로그인 사용자를 나눠 센다. 실패와 재시도로 숫자를 중복하지 않는다.
13. 비회원을 계정에 연결하면 같은 uid의 데이터를 유지한다.
14. 탈퇴 문안과 삭제 범위, 남는 데이터가 같아야 한다.
15. 감사 로그에는 행위와 필드 이름만 남기고 이전 본문은 남기지 않는다.
16. `해당 없음`과 MVP 이후 항목은 구현하지 않는다.
17. 화면 문장만 한국어, English, 日本語로 바꾸고, 코드와 데이터베이스 항목은 영어로 둔다.
18. AI는 서버에서 스키마 JSON(enum과 필수 칸)으로만 받는다. 키워드로 메뉴를 고르지 않는다. 저장하지 못했으면 한 번 다시 묻고, 그래도 안 되면 사실대로 알린다.
19. 클라이언트는 자기 uid 아래만 읽고, 쓰기는 Admin SDK만 한다. 주 DB는 삭제 보호를 켜고, 보조 DB는 서버 트리거로만 복제한다.
20. 글자크기·줄간 거리 5단계와 행 펼치기(탭 또는 더블클릭, 체크는 체크박스만)를 기본 UI로 넣는다.

## 21. 개발 Agent 프롬프트 골격

섹션 20이 모두 `예`이거나 이유 있는 `해당 없음`일 때, 이 골격의 중괄호를 기획서 값으로 바꾼다. 아래는 aiAssistant로 바꾼 결과다. 기본값 그대로인 칸은 한 줄로 묶는다. `해당 없음`과 MVP 이후 항목은 끝의 제외 목록으로 옮긴다.

```text
프로젝트: aiAssistant / 통합 AI 업무 어시스턴트
기획 기준: 업무용 프로그램 개발 표준 세부 기획서 1.4 / 2026-10-19
저장소: https://github.com/byki0304/aiassistant
로컬 확인: flutter run -d chrome
스택: Flutter 웹 PWA(Riverpod 3), Node.js 22 Cloud Functions v2, Firebase aiassistant-49b02(Auth, Firestore aiassistant, Storage). 보조 DB: Firestore aiassistant-backup(트리거 복제).
AI: Gemini REST, 모델은 GEMINI_MODEL(기본 gemini-3.8-flash), responseSchema, thinking low. 키는 Secret Manager GEMINI_API_KEY.
외부 API: OpenWeather(OPENWEATHER_API_KEY), ExchangeRate-API v6(EXCHANGE_RATE_API_KEY), Google News RSS.
호스트: Vercel, main 푸시, bash tool/vercel-build.sh, https://aiassistant-xi-eight.vercel.app. 리전: asia-northeast3.
폴더: lib/main.dart, lib/pages(셸과 레이아웃 3개), lib/features, lib/shared, functions/, web/brand/, app_icons/, tool/.
문안: 한국어, English, 日本語. 기준 문안은 한국어. 코드와 DB는 영어.

한 줄 약속: 가운데 입력창에 넣은 말, 음성, 문서를 AI가 읽어 텍스트·표·도표로 답하고, 일정·장부·날씨·환율·뉴스는 해당 메뉴에 남긴다.

섹션 19의 20문장을 여기에 그대로 붙인다.

아이디어
- 상황: 혼자서 말·음성·문서로 일정과 장부를 관리하고 날씨·환율·뉴스를 조회한다.
- 첫 안내: 말, 음성, 문서를 가운데 창에 넣으면 텍스트·표·도표로 답하고 해당 메뉴에 남깁니다.
- 성공: 서버가 저장한 뒤에만 '메뉴' 자동 저장됨 (바로가기)와 ✓✓가 보이고, 해당 메뉴가 열린다.
- 실패: 대상 없음, 시각 누락, 도시 없음, 환율 실패, 형식, 20MB, 구형 Office, 키 없음, 연결. 사실대로 알린다.
- 데이터 없음: 저장된 데이터가 없습니다. 중앙 AI 입력창으로 내용을 넣어 주세요.
- 비회원 / 로그인: 기능은 같다. 게스트는 Google 연결로 기록을 유지한다.
- 관계: 혼자.
- 참고와 차이: 대화로 끝나지 않고 메뉴에 남으며, 기존 항목을 말로 옮기고 고치고 지운다.
- 스타일: 민트 낙서 배경, 잉크 테두리의 파스텔 스티커 카드, 노란 바탕의 은색 로봇.
- MVP / 이후: 웹 PWA까지. 관리자·통계, 스토어, 푸시, 다크 모드, 결제는 이후.

포함할 동작: 만들기(AI, 승인 칩, 조회 기록), 목록, 행 펼치기, AI 수정(옮기기·취소·장부 수정), 지우기, 120시간 자동 삭제, 파일 올리기, 말로 시키기, 계산, 뉴스 PDF.
데이터 필드: B-07-01 그대로.
AI 스키마: targetMenu와 saveMode는 enum. 필수 칸은 targetMenu, saveMode, summaryText, balances. schedule은 action과 startAt 필수, 순서 action, targetId, startAt, endAt, allDay, title. balances 항목은 action과 amount 필수. maxLength는 쓰지 않는다.
AI 문맥: 지금 시각과 요일, 기존 일정(id | 제목 | 시작 | 상태), 최근 장부(id | 내역 | 종류 | 금액 | 시각).
실패 처리: 아무것도 저장되지 않았으면 한 번 더 묻고, 그래도 안 되면 notApplied 문장. 일부만 저장했으면 partlyApplied 문장.
홈 형태: 위 입력 카드, 프리셋 3개, 아래 대화(최신이 위). 메뉴를 열면 데스크톱 46:54, 휴대폰 가로 47:53, 휴대폰 세로 42/58.

## 남은 일 (1.4 기준 코드와 표준의 차이)

1. 목록과 대화 삭제에 확인 단계를 넣는다(`선택한 N개를 삭제합니다.` 문안은 이미 있다). 또는 지금처럼 두 단계로 유지한다고 B-05-06에 확정한다.
2. 업로드 원본의 보존 시간을 정한다(예: 분석 성공 뒤 삭제, 또는 N시간). 정하기 전까지는 탈퇴할 때 삭제된다.
3. `web/brand/prompts.md`를 로봇 기준 7종으로 다시 쓰고, 썸네일과 상태 그림을 만든다.
4. README의 콘솔 체크리스트에 이메일/비밀번호 로그인을 더한다. 환율 API가 키를 쓰는 서비스라는 점도 적는다.
5. 감사 로그 필드 이름을 표준(`targetUid`, `changedFields`)에 맞출지 정한다.
6. Gemini 호출 횟수 제한 또는 예산 알림을 둔다.
7. 탈퇴 문안에 "이 기기의 계산 기록과 화면 설정은 남습니다"를 넣거나, 탈퇴할 때 함께 지운다.
8. 버려진 게스트 계정의 데이터 정리 방법을 정한다.
9. Firestore TTL 정책이 있는지 확인하고, PITR을 켤지 다시 정한다.

1.3에서 TempBox가 확정한 값(비회원 24시간·로그인 240시간, 한 번 받기 잠금 10분, 페어링 코드 15분 5회, 관리자 통계)은 "한 번 받고 사라지는 상자" 유형의 선택 패턴으로 남는다. 시나리오가 그 유형이면 1.3의 해당 칸을 가져온다.
